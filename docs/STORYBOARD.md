## 用户角色定义

### 1. 普通用户 (USER)
- **描述**: 系统的基本用户，可以浏览资产、参与拍卖、进行预测等
- **权限**: 
  - 浏览资产列表
  - 查看资产详情
  - 参与拍卖
  - 进行预测下注
  - 购买TOT代币
  - 查看排行榜
  - 使用地图功能

### 2. 提交者 (SUBMITTER)
- **描述**: 可以提交资产数据的用户（通常是房地产开发商）
- **权限**: 
  - 普通用户的所有权限
  - 提交资产数据
  - 上传资产证明文件
  - 查看自己提交的资产状态

### 3. 审核员 (REVIEWER)
- **描述**: 审核提交的资产数据的用户
- **权限**: 
  - 普通用户的所有权限
  - 查看待审核资产列表
  - 批准或拒绝资产
  - 查看审核历史
  - 生成资产合同PDF

### 4. 管理员 (ADMIN)
- **描述**: 系统管理员，拥有最高权限
- **权限**: 
  - 所有角色的权限
  - 管理用户账户
  - 管理资产数据
  - 管理科技项目
  - 查看系统统计
  - 配置系统参数

### 5. 投资者
- **描述**: 投资科技项目的用户
- **权限**: 
  - 普通用户的所有权限
  - 浏览科技项目
  - 投资项目
  - 查看投资记录

### 6. 资产所有者
- **描述**: 持有RWA资产的用户
- **权限**: 
  - 普通用户的所有权限
  - 查看持有的资产
  - 交易资产份额
  - 购买ETF

## 用户场景

### 场景1: 用户注册和登录 (S-001)

**场景编号**: S-001  
**场景名称**: 用户注册和首次登录  
**用户角色**: 新用户  
**前置条件**: 用户访问系统首页  
**涉及功能点**: F-AUTH-001-v1.0, F-AUTH-002-v1.0

#### 操作步骤

1. **访问注册页面**
   - 操作位置: 首页 -> 点击"注册"按钮
   - 输入数据: 无
   - 验证点: 页面跳转到注册表单

2. **填写注册信息**
   - 操作位置: 注册表单
   - 输入数据:
     - 用户名: `testuser123`
     - 密码: `Test123456`
   - 验证点: 表单验证通过

3. **提交注册**
   - 操作位置: 注册表单 -> 点击"注册"按钮
   - 输入数据: 无
   - 验证点: 
     - 显示"注册成功"消息
     - 返回助记符（用户需要保存）
     - 自动跳转到登录页面

4. **登录系统**
   - 操作位置: 登录页面
   - 输入数据:
     - 用户名: `testuser123`
     - 密码: `Test123456`
   - 验证点:
     - 显示"登录成功"消息
     - 跳转到首页
     - 显示用户信息

#### 预期结果
- 用户成功注册并登录系统
- 用户获得JWT token
- 用户信息正确显示

#### 异常情况处理
- **用户名已存在**: 显示错误消息"用户名已被使用"
- **密码强度不足**: 显示错误消息"密码必须至少8个字符，包含字母和数字"
- **登录失败**: 显示错误消息"用户名或密码错误"

### 场景2: 资产提交和审核流程 (S-002)

**场景编号**: S-002  
**场景名称**: 提交者提交资产，审核员审核  
**用户角色**: SUBMITTER, REVIEWER  
**前置条件**: 
- 提交者已登录
- 审核员已登录  
**涉及功能点**: F-ARS-001-v1.0, F-ARS-003-v1.0, F-ARS-006-v1.0, F-ARS-007-v1.0

#### 操作步骤

1. **提交者登录**
   - 操作位置: 登录页面
   - 输入数据: 提交者账户信息
   - 验证点: 登录成功

2. **提交者访问资产提交页面**
   - 操作位置: 导航菜单 -> "资产入库"
   - 输入数据: 无
   - 验证点: 显示资产提交表单

3. **提交者填写资产信息**
   - 操作位置: 资产提交表单
   - 输入数据:
     - 城市: `Taipei`
     - 面积: `100`
     - 债务金额: `1000000`
     - 项目名称: `Test Project`
   - 验证点: 表单验证通过

4. **提交者上传证明文件**
   - 操作位置: 资产提交表单 -> 文件上传区域
   - 输入数据: 选择资产证明PDF文件
   - 验证点: 文件上传成功

5. **提交者提交资产**
   - 操作位置: 资产提交表单 -> 点击"提交"按钮
   - 输入数据: 无
   - 验证点:
     - 显示"提交成功"消息
     - 资产状态为"待审核"

6. **审核员查看待审核资产**
   - 操作位置: 审核员账户 -> "待审核资产"页面
   - 输入数据: 无
   - 验证点: 显示新提交的资产

7. **审核员审核资产**
   - 操作位置: 资产详情页 -> 点击"批准"按钮
   - 输入数据: 无
   - 验证点:
     - 显示"审核成功"消息
     - 资产状态变为"已批准"
     - 资产出现在公开资产列表中

#### 预期结果
- 资产成功提交并通过审核
- 资产在系统中可见
- 提交者和审核员都能看到相应的状态更新

#### 异常情况处理
- **提交者权限不足**: 显示错误消息"您没有提交资产的权限"
- **资产信息不完整**: 显示错误消息"请填写所有必填字段"
- **审核员拒绝资产**: 资产状态变为"已拒绝"，提交者收到通知

### 场景3: 参与拍卖 (S-003)

**场景编号**: S-003  
**场景名称**: 用户参与资产拍卖  
**用户角色**: USER  
**前置条件**: 
- 用户已登录
- 用户有足够的TOT代币余额
- 存在活跃的拍卖  
**涉及功能点**: F-AUC-001-v1.0, F-AUC-002-v1.0, F-AUC-004-v1.0

#### 操作步骤

1. **用户浏览拍卖列表**
   - 操作位置: 导航菜单 -> "拍卖"
   - 输入数据: 无
   - 验证点: 显示所有活跃的拍卖

2. **用户查看拍卖详情**
   - 操作位置: 拍卖列表 -> 点击某个拍卖
   - 输入数据: 无
   - 验证点: 显示拍卖详细信息（资产信息、起拍价、当前最高价等）

3. **用户检查TOT余额**
   - 操作位置: 用户账户页面
   - 输入数据: 无
   - 验证点: 显示当前TOT余额

4. **用户参与拍卖（夺取资产）**
   - 操作位置: 拍卖详情页 -> 点击"夺取"按钮
   - 输入数据:
     - 出价消息: `我要这个资产`
   - 验证点:
     - 显示交易构建成功
     - 提示用户签名交易

5. **用户签名交易**
   - 操作位置: 钱包扩展程序
   - 输入数据: 确认交易签名
   - 验证点: 交易签名成功

6. **系统验证交易**
   - 操作位置: 后端自动处理
   - 输入数据: 交易签名
   - 验证点:
     - 交易验证成功
     - 资产所有权转移
     - 原所有者获得95%的支付（10%溢价机制）

#### 预期结果
- 用户成功获得资产所有权
- 原所有者获得相应支付
- 拍卖状态更新为"已完成"

#### 异常情况处理
- **余额不足**: 显示错误消息"TOT余额不足"
- **拍卖已结束**: 显示错误消息"该拍卖已结束"
- **交易失败**: 显示错误消息"交易失败，请重试"

## 业务流程

### 资产入库流程

```
[提交者] -> 提交资产数据 -> [待审核] -> [审核员] -> 审核资产 -> [已批准/已拒绝]
                                                              |
                                                              v
                                                         [资产上链]
                                                              |
                                                              v
                                                         [公开可见]
```

### 拍卖流程

```
[创建拍卖] -> [活跃拍卖] -> [用户出价] -> [交易验证] -> [资产转移] -> [拍卖完成]
                                                              |
                                                              v
                                                         [原所有者获得95%支付]
```

### 预测市场流程

```
[创建市场] -> [用户下注] -> [市场关闭] -> [结果公布] -> [奖励分配]
```

### RWA交易流程

```
[资产上架] -> [用户购买份额] -> [交易验证] -> [持有记录更新] -> [份额可交易]
```
